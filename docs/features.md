# Features

What the server does today, by area. See [limitations.md](limitations.md) for what it does not.

## Language

Syntax is covered up to Java 25 (records, sealed types, pattern matching, switch expressions, text
blocks, module declarations, module imports, compact source files, and so on), plus primitive types
in patterns, `instanceof` and `switch` as a preview feature.

## Navigation

Go to definition / declaration / type definition / implementation, find references, document highlights, workspace symbols (also dependency and JDK types, matched by CamelCase abbreviations such as `CHM`), call hierarchy, type hierarchy; implementations and subtypes include local and anonymous classes (`new Runnable() {…}`, also with a diamond: `new Comparator<>() {…}`) and enum constant bodies, and rename updates their overrides; names in Javadoc (`{@link Foo#bar(int)}`, `{@linkplain}`, `{@value}`, `@see`, `@throws`, `@param`) resolve for go to definition, hover, highlights and references, and are updated by rename

## Completion

Members, locals, static members, types (auto-import for types not yet imported), keywords, snippets and context-aware templates (`soutv` / `soutp` / `soutm` print the nearest variable, the method parameters or the method name; `iter` / `itar` / `ritar` loop over the nearest iterable or array with the element type and name filled in; `souf`, `thr`, `psfs` …), postfix templates (`.var` `.if` `.else` `.for` `.iter` `.itar` `.fori` `.forr` `.nn` `.inst` `.reqnonnull` `.synchronized` `.assert` `.arg` `.format` `.stream` `.opt` `.switch` `.try` `.serr` …), override stubs, Javadoc tags; by expected type: implementations after `new` (`List` → `ArrayList`, workspace implementations, those declared in the current file first; an interface or abstract class becomes an anonymous class with stubs for its abstract methods, type arguments taken from the expected type), lambda templates for functional interfaces, annotations filtered by their `@Target`; inside Javadoc: types after `{@link}` / `@see` / `@throws`, members after `#`, parameter types inside `{@link #foo(…)}` (whole overload signatures first), parameter and type parameter names after `@param` and block / inline tags, constants of the expected type (`TimeUnit.SECONDS`, `BigDecimal.ZERO`); ranked by expected type, scope distance and in-file usage frequency

## Information

Hover (signature + Javadoc; on a call, the signature with the receiver's type arguments and the inferred method type arguments substituted, e.g. `Integer get(Object key)` on a `Map<String, Integer>`, followed by the declared one; also for library classes that ship sources — missing sources jars are downloaded in the background on first navigation; values of constant fields and `final` locals, evaluated from constant expressions in source or read from class files), signature help, semantic tokens (full / range / delta)

## Structure

Document symbols, folding (including `//region` and `<editor-fold>` comments), selection ranges, clickable `http(s)` links in comments, Javadoc and string literals

## Editing

Rename (including override chains, constructors, the matching file and Lombok accessors); formatting (indentation, spacing within a line, blank lines to keep and between members, optionally the placement of `{`, wrapping of lines longer than the right margin set by `max_line_length` at argument lists, method chains, binary operators and `throws` / `implements` lists; configured through `.editorconfig`: right margin (`max_line_length`), indent style and size, continuation indent, `case` and top-level member indentation, blank lines, spacing around operators, before and within parentheses, brace style, final newline — keys listed in [docs/configuration.md](configuration.md), editor tab settings apply where `.editorconfig` sets nothing) and on-type formatting (indent on Enter, re-layout of the current line after `}` and `;`, a Javadoc skeleton with `@param` / `@return` / `@throws` after typing `/**` and Enter above a declaration); inlay hints (types of `var`, parameter names, types along multi-line method chains); code lens (reference and implementation counts; clicking lists them in VS Code, or through a configurable client command); a newly created empty `.java` file is filled with its package declaration and a class of the same name

## Quick fixes

Import, create method / field / local variable, create a method or field in another class (`other.foo(x)`, `Util.foo(x)`, `other.count`, `Util.LIMIT`; an abstract method or constant in an interface) or a constructor for `new Foo(a, b)` without a matching one, adding the imports the target file needs, remove an extra argument or add a matching parameter to a `private` / `static` method (other calls get a default value), change a parameter type of such a method to the argument's type when the other calls still fit, create class / interface / enum / record / annotation in a new file, add `throws` or surround with try/catch, add a cast, add missing enum `switch` cases, initialize a variable, replace string `==` with `equals()`, remove unused variables / fields / methods (keeping side effects of the initializer), widen the visibility of an inaccessible member, remove `final` from an assigned variable, change a variable or return type to match the value, add a missing `return`, make a class abstract

## Generation and refactoring

Organize imports (and import insertion) following the import layout and the on-demand import threshold of `.editorconfig` (`ij_java_imports_layout`, `ij_java_class_count_to_use_import_on_demand`, `ij_java_names_count_to_use_static_import_on_demand`); fix all behavior-preserving problems of a file at once (`source.fixAll`, e.g. on save); generate constructor / getter / setter / `toString` / `equals` / `hashCode` / delegate methods for a field; generate a builder (a static nested `Builder` with one chained setter per parameter and `build()`, plus `builder()`) from a constructor or record; implement abstract methods; add `@Override`; extract local variable / method (with the exceptions it actually throws and the type parameters it uses) / constant / field; encapsulate a field (make it private, generate accessors and rewrite reads and writes outside the class into accessor calls); inline constant; inline local variable / single-statement method; remove unused parameter; move parameter; change signature (edit a method's or constructor's declaration in place — add, remove, reorder or rename parameters, change their types, the name or the return type — then "Update usages to the new signature" on the declaration rewrites every call, `super(...)` / `this(...)` and enum constant argument, the overriding and overridden declarations in the whole hierarchy including anonymous and local classes, method references whose parameters did not change, `@param` tags and uses of renamed parameters in the body; new parameters get a variable of the same name and a compatible type in scope at the call, or a default value; dropping an argument with side effects or a method reference that no longer fits is refused with the location); introduce parameter (a selected expression becomes a new parameter of a `private` / `static` method, and every call passes it with the method's parameters replaced by the call's arguments); pull a method up to any workspace superclass; extract interface (public instance methods into a new interface the class implements, marking them `@Override`); move class and package (moving or renaming a `.java` file or a whole directory in the editor updates the package declarations and the imports that refer to the moved classes; classes moved together do not import each other); convert anonymous class to lambda; invert `if`; split `if (a && b)` into nested `if`s and merge them back; surround selected statements with `if` / `if-else` / `while` / `try-catch` / `try-finally` / `synchronized` / a block; replace `var` with an explicit type and an explicit type with `var` (only when the initializer has exactly the declared type and is not inferred from the target); add braces; split / join declaration and assignment; flip comparisons and `equals()`; De Morgan (`a && b` ↔ `!(!a || !b)`); remove an `else` after a branch that ends with `return` / `throw` / `break` / `continue`; `?:` ↔ if / else; lambda ↔ method reference; indexed `for` → enhanced `for`; old-style `switch` → `->` cases; a `switch` whose branches all assign the same variable or all return → a `switch` expression (merged into a preceding declaration without initializer); `if` / `else if` chains comparing one value with constants, enum constants or strings → `switch`; convert a data class (private final fields set by one constructor) to a `record`, keeping validation in a compact constructor; string concatenation → `String.format(...)`, or → a text block when it is made of string literals spanning several lines; create a field for a constructor parameter

## Frameworks

Member synthesis for Lombok (accessors with `AccessLevel`, `@Accessors(fluent / chain / prefix)`, the constructor annotations with `staticName` / `access`, `@Builder` with its options, `@Builder.Default` and `@Singular`, `@Builder` on constructors and static methods, builders of generic classes, records and methods carrying their type parameters (`Pair.<String, Integer>builder().first("a").build()` is a `Pair<String, Integer>`), `@SuperBuilder` with the generated builder hierarchy (setters inherited from the parent's builder keep returning the subclass builder, `build()` returns the subclass, `toBuilder` when requested), `@With`, `@ToString` / `@EqualsAndHashCode`, `@FieldNameConstants`, `@StandardException`, `@FieldDefaults`, `@UtilityClass`, `@Delegate`, `val` / `var`, the logging annotations; `lombok.config` files apply to the sources in their directory and below, nearer files overriding farther ones); Spring MVC / JAX-RS endpoints, searchable by path through workspace symbols (`/api/users`, `GET /orders`); OpenFeign clients and Spring HTTP interfaces linked to the matching endpoints across services (go to definition / implementation, references in both directions, hover listing the target), preferring the service whose `spring.application.name` matches; Spring bean injection: go to implementation on an injected field or parameter (`@Autowired` / `@Inject` / `@Resource` fields and setters, constructor parameters of beans including constructors generated by Lombok, `@Bean` method parameters, and fields a constructor assigns from them) lists the bean definitions it receives — classes annotated `@Component` / `@Service` / `@Repository` / `@Controller` / `@Configuration` (directly or through a custom annotation), `@Bean` methods, Spring Data repositories and `@FeignClient` / `@Mapper` interfaces — matched by type including type arguments and narrowed by `@Qualifier` / `@Named`, `@Resource(name = ...)`, `@Primary` and the field or parameter name, with `List` / `Set` / `Map<String, …>` / array injection receiving all candidates; hover on an injection point lists the injected beans, and find references on a bean class or `@Bean` method includes the injection points that receive it; Spring configuration keys from `application*.properties` / `.yml` in `@Value("${...}")` and `Environment.getProperty(...)`: completion, go to definition, hover with the value, and a warning for undefined keys without a default; inside `application*.properties` / `.yml` themselves: completion of keys and values, hover, go to definition and warnings for unknown or deprecated keys, from `spring-configuration-metadata.json` in dependencies and build output and from `@ConfigurationProperties` classes in the workspace

## Projects

Maven (including `test-jar` dependencies and Eclipse PDE / Tycho bundles; the local repository is located like Maven does, from `MAVEN_OPTS`, the user and the installation `settings.xml`, or set with `maven.localRepository`), Gradle, manual configuration via `java-analyzer.toml`; per-module language level and preview setting; automatic JDK discovery

## Libraries

Going to a dependency class opens the source from the sources jar / `src.zip`, or, when no source is available, a stub generated from the class file with method bodies decompiled from bytecode (lambdas, anonymous classes, loops, `switch`, `try` / `finally`, `synchronized`; setting `decompiler`, also available as `java-analyzer decompile`); inside these read-only files, navigation, hover, references and highlights work for members, locals and calls as in project files (references on a declaration in a stub find the call sites in the project)

## Debugging

`java-analyzer dap` is a Debug Adapter Protocol server speaking JDWP directly: launch (class path computed from the project model, `-Dfile.encoding` from the project's source encoding unless `vmArgs` sets it) or attach, line / conditional / hit-count / log breakpoints, exception breakpoints, stepping, threads and stack frames with sources from the workspace, sources jars and `src.zip`, variables (fields, array pages, strings, boxed values, enum names), setting variables, and evaluating Java expressions with method calls, `new`, operators, casts and `instanceof` (watch, console, conditions and log points), completion in the evaluate field, watch and console (locals, members of the runtime type, static members, types and packages, without running code in the debuggee); hot swap of recompiled classes (`redefineClasses`); see [docs/editors.md](editors.md) for VS Code, nvim-dap, Helix and Zed; the same run / test class path, JDK and source encoding are available to clients through the `java-analyzer/projectClasspath` request

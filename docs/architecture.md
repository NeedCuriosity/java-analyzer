# 架构

## 分层

```
java-analyzer (bin)
      │
     ide ──────────────┬────────────────┐
      │          ide-completion   ide-diagnostics
      └───────┬────────┴────────────────┘
           ide-db
              │
             hir
              │
           hir-ty
              │
           hir-def
        ┌─────┴──────┐
     syntax      classfile      project-model
        │            │               │
     parser          └──── base-db ──┘
                             │
                            vfs
```

依赖只能自上而下。`ide` 是对外的边界：它的 API 只用 `FileId`、`TextSize`、`TextRange`
和自己定义的结果类型，LSP 类型只出现在 `java-analyzer` 里。

## 增量计算

所有分析都是 [salsa](https://github.com/salsa-rs/salsa) 查询。输入只有两类：

- `SourceFile`：每个源码文件一份，字段是文本；
- `Workspace`（单例）：文件集合、工程图、二进制类路径。

关键的隔离点是 **ItemTree**：每个文件先降成只含声明签名的 `ItemTree`（不含方法体）。
在方法体里敲字会让该文件的 `ItemTree` 重新计算，但结果与之前相等，于是依赖它的
全局查询（类索引、其它文件的推断结果）全部保留。方法体推断是按"体"（一个方法、
一个字段初始化式或一个初始化块）的惰性查询。

语法树占内存多，只用 LRU 保留最近的一批；`ItemTree` 和签名常驻。

## 增量重解析

在方法体里敲字是最常见的编辑。`parse` 查询会拿当前文本和该文件上一次的解析结果比较，
如果改动完全落在某个方法体（或初始化块）的花括号之内，并且改动后那段文本仍然是一个
花括号配对、能被块语法完整消费的片段，就只重新解析这个块，再把新的子树换进旧树
（`Parse::reparse`）。其它情况退回整文件解析。

增量结果必须与整文件解析逐节点相同——这一点由语料测试和模糊测试（`fuzz/` 下的 `reparse`
目标）持续校验，所以它只是加速手段，不影响查询结果的确定性。

## AST 的代码生成

节点结构体和枚举的声明由 `cargo xtask codegen` 从 `crates/syntax/ast.def` 生成到
`crates/syntax/src/ast/generated.rs`；访问器手写在 `nodes.rs` 里。CI 用
`cargo xtask codegen --check` 保证两者一致。`SyntaxKind` 是手写的，生成器只校验
`ast.def` 引用的种类都存在。

## 统一签名模型

`.java` 源文件和 `.class` 文件都降成同一种 `ClassData`（类型参数、父类型、字段与方法的
签名、修饰符、注解）。`hir-ty` 及以上不关心一个类来自源码还是二进制。
类用驻留的二进制名（`java/util/Map$Entry`）标识，字段和方法用"类 + 下标"标识。
同一个二进制名有多份声明时（多个模块各有一个 `com.acme.Application`、源码和 jar 里各有一份、
多个 jar 里重复的类），每一份是独立的 `ClassId`：按源码 > 依赖 > JDK 排第一的是主副本，
它的 id 就是二进制名，不看上下文的查找（JDK 里的知名类等）返回它；其余副本的 id 带着来源
（源码文件或类路径容器）。从一个文件出发解析名字时，按模块依赖挑这个文件看得到的那一份：
本模块、依赖（按依赖列表的顺序）、散落文件、JDK。成员类型和外层类跟随所在的那一份；
查找引用、实现、类型层次、工作区符号都区分各个副本。类型相容性按名字认类，副本之间可以互相赋值。

Lombok 的成员也在这一层合成（`hir-def/src/lombok.rs`）：源码降成 `ClassData` 之后，按类和
字段上的注解追加 getter / setter / 构造器 / `builder()` / `log` 字段等，并标记为合成成员。
上层因此不需要知道 Lombok 的存在；合成成员没有源码位置，跳转会落到触发它的字段或类上。

## 方法体推断

`hir-ty::infer` 直接在语法树上做名字解析和类型推断，结果按节点的文本范围索引：
表达式类型、名字引用的解析结果、局部变量、调用的重载信息、诊断。

推断不出来的地方是 `Ty::Unknown`。它与任何类型相容，不产生诊断；上层功能都必须对它容错。
这是诊断"保守"的来源：只有确定是错的才会报。

## 读写模型

- 主线程持有 `AnalysisHost`，是唯一的写入者：应用文本变更、工程模型变更。
- 请求在线程池里对着 `Analysis` 快照计算。主循环不做任何分析工作。
- 写入时 salsa 让仍在进行的查询以 `Cancelled` 展开，对应的请求回复 `ContentModified`，
  由客户端重发。

客户端不支持动态注册文件监听时，服务器自己监听工作区目录（`notify`），
两条路径最终都汇到同一个"以磁盘当前状态为准"的处理函数。

线程池分三档：延迟敏感（补全、签名帮助，有专属线程）、普通（悬停、跳转、高亮、诊断）、
后台（索引预热、查找引用、查找实现）。后台任务只占用一小部分线程。

## 补全

光标处的代码通常是残缺的。补全在光标处插入一个占位标识符后重新解析，在这棵"假树"上判断
语法位置；类型和作用域等语义信息仍从数据库里的原始文件上取，通过文本范围把假树里
光标之前的节点对应回原树。

## 查找引用

先按名字做纯文本筛选（绝大多数文件根本不含这个标识符），只对命中的位置做语义确认。
私有成员和局部符号的搜索范围直接缩小到所在文件。

## 依赖库里的类

类路径启动时并行扫描成"摘要"（名字、访问标志、父类型），结果按 jar 的路径、大小、
修改时间缓存到磁盘。完整的类文件在第一次被用到时才解析。

跳转到依赖类时，`ide` 只返回"哪个类的哪个成员"；由 `java-analyzer` 从 sources jar /
`src.zip` 解压出对应的源文件（没有源码时写一份按签名生成的桩代码），再在文本里按名字和
形参个数定位声明。

## 流分析与检查项

`ide-diagnostics/src/flow.rs` 按 JLS §14.22 的规则在语法树上判断每条语句"能否正常结束"，
由此报告不可达的语句和缺少 `return` 的方法。它只在没有语法错误的文件上运行；`switch` 没有
精确建模，遇到时把结论标成"不确定"，不报告缺少 `return`。

确定赋值（JLS §16）沿语句结构跟踪每个没有初值的局部变量：`if` 取两个分支的交，循环体里的赋值
在循环之后不算数，`try` 要求 try 块和所有 catch 都赋值（或 finally 里赋值）。拿不准的地方
（条件表达式里的赋值、`switch`、带标签的跳转）一律按"已赋值"近似，所以只会漏报不会误报。

受检异常检查在 `ide-diagnostics/src/exceptions.rs`：取调用解析到的方法的 `throws`
（以及 `throw new X()` 的类型），向外找能接住它的 `catch` 或所在方法的 `throws`。
lambda、匿名类、初始化块、`throw 变量`、try-with-resources 隐含的 `close()` 都不判断。

同一个文件里还有几个只看表达式的检查项（`==` 比较字符串、自我赋值、自我比较），
用推断结果取类型，不做数据流。

## 修改代码

重命名、代码操作、格式化都只产出 `SourceChange`（按文件分组的文本编辑，外加可选的文件改名），
不直接碰文件；`java-analyzer` 把它转成 `WorkspaceEdit`。

- **重命名**（`ide/src/rename.rs`）：先把目标归一到覆写链的最顶层声明，再复用查找引用收集
  所有位置。类改名会连带构造器和同名的 `.java` 文件；记录组件连带访问器。新名字与同作用域
  的已有声明冲突、或目标在依赖库里时拒绝。
- **代码操作**（`ide/src/assists.rs`）：每个操作是一个"能否适用 + 生成编辑"的函数，
  在光标或选区上逐个尝试。针对诊断的快速修复（导入、删除未使用的 import）与之共用实现。
- **格式化**（`ide/src/formatting.rs`）：按语法树的嵌套深度重排每行缩进并去掉行尾空白，
  不改动行内的 token，也不断行；文本块和注释内部保持原样。
- **较大的重构**（`ide/src/assists/refactor.rs`）：提取方法先算出选区与外界交换的局部变量
  （之前声明、选区里用到的变成形参；选区里产生、之后还要用的变成返回值，多于一个就放弃），
  选区里有跳出选区的 `return` / `break` / `continue` 时不提供。内联变量要求变量只赋值一次，
  且初值依赖的局部变量之后不再被改写。
- **修改签名**（`ide/src/signature_tracker.rs`、`ide/src/change_signature.rs`）：用户直接改声明，
  服务器在每次编辑应用之前用编辑前的语法树记录：编辑第一次落在某个方法 / 构造器的签名头
  （返回类型起到形参列表的右括号）上时，记下当时的签名头原文，之后的编辑只移动、伸缩这段范围。
  这样记下的总是这一轮修改开始之前的签名，存盘、格式化、改别处都不影响它；按新签名更新完用法
  （客户端执行 `java-analyzer.acceptSignature` 命令）、删掉声明或关闭文件时结束。更新用法时，
  新旧形参先按名字、再按位置对应；按旧签名找出覆写链（含局部类、匿名类和菱形匿名类），按旧名字
  搜索调用处，解析到覆写链上的方法、或者接收者属于覆写链且旧签名在同名方法里胜出的调用才改。
  要删掉的实参有副作用、重排会改变副作用的先后、方法引用和新形参对不上时拒绝并给出位置。
- **移动类**（`ide/src/move_class.rs`）：由 `workspace/willRenameFiles` 触发。服务器从文件原来的
  路径和包名反推源码根，算出新目录对应的包名，再改写 package 声明和各处的 import；
  同目录下只改文件名时，转成对同名顶层类的重命名。
- **Code lens**（`ide/src/code_lens.rs`）：列出时只看语法，数量在 `codeLens/resolve` 里才算。
- **Inlay hints**（`ide/src/inlay_hints.rs`）：`var` 的推断类型、字面量实参的形参名，
  只在类型或含义不明显的地方给出。

## 测试

- 语法：`crates/syntax/test_data` 下的语料（`ok/` 必须零错误，`err/` 必须能恢复），
  加上"树文本 == 原文"的往返检查和"增量 == 全量"的一致性检查。
- 模糊测试：`fuzz/` 下的 `parse`（不 panic、无损）和 `reparse`（增量与全量一致）。
- 基准：`cargo bench -p syntax`（整文件解析、增量重解析、语料）。
- 端到端：`java-analyzer` 的测试在进程内启动服务器，经内存通道走完整的 LSP 会话
  （手动配置工程和 Maven 目录约定各一个）。
- 语义与 IDE 功能：`test-fixture` 提供带 `$0` 光标标记的多文件内联 fixture，并自带
  `minicore`（手写的 `java.lang` / `java.util` 最小源码桩），单元测试不依赖 JDK。
- 真实工程：`java-analyzer parse` 做语料解析，`java-analyzer analysis-stats` 做全量分析并
  输出表达式类型已知率和语义诊断数（合法工程上应接近 0）。
